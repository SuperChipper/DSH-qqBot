# B 模型检索强度短对照：0.6 / 0.8 / 0.9

用户反馈 B 的肥鱼音色弱了一些，并选择“保留 B，先试增强检索的短对照”。
本轮生成三档短试听，**保留 B 默认、index 默认仍为 0.6，没有选定新默认，也没有训练**。

## 比较条件

- 全部使用 B `feiyu40k_aux70_ab_20261102_e10.pth`、SID 0，原 hi 的目标 SID 0 检索库。
- 同一声源、相同人工目标 F0，每次推理重设 Python / NumPy / Torch 随机种子 20261103。
- 唯一主动变化的推理参数是 index_rate：0.6、0.8、0.9。
- pitch=0、protect=0.35、rms_mix=0.15、filter_radius=7；输入使用原分离人声，未用 HP5 替换。
- 不启用 V9 的实验检索特征平滑。固定 F0 测生成音色，不将此当作自动提取全流程测试。
- 后处理统一为现有 safe 换气、noise_reduce=0.5、presence=4、debuzz=0.85、air=0；
  同一后处理算法会随输出产生不同的掩码，这属于参数改变后的实际处理结果。
- 每个试听片段分别匹配三档人声 RMS，共用同一伴奏（gain=0.9）及共同峰值增益，
  不对任何一档单独加亮、压缩或去噪。导出器没有再单独调音量。

## 验证与结论边界

全部九次推理完成。每个声源的三份实际 F0 dump 哈希完全一致。
对处理后干声复核 RMVPE / CREPE：魔法女仆、CIRCE 与 Blue 第一个窗口均未检出相对目标的八度分歧帧；
Blue 第二个窗口三档分别为 2/3/3 帧，与原目标中极短约 139 Hz 的疑点有关。
未据这点差异判断旋律是否错误，也未把音高指标当成音色相似度评分。

默认源码、B 权重、检索库的前后哈希一致。当前仍为 B + 0.6。
三档哪一个更像肥鱼、是否咬字变糊或加重 Blue 电音感，尚待用户试听，不自动以较高数值判胜。
