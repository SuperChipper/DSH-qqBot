
默认前后各带 2 秒上下文，复用已有 stem，只重跑这段 RVC；按原采样时间轴截取、用上下文限幅度匹配
响度、80 ms 线性交叉淡化，然后整轨润色/立体声混音。拼接后的原始 RVC 轨在区间外逐样本保持原值；
全轨后处理与峰值归一化仍可能改变最终区间外的波形。修复拒绝局部改调，`repair.json` 保存区间和增益。

每次 RVC 另存 `02_f0.csv`（秒,目标 Hz；0 Hz 表示清音）。手工修完后用 `--f0-file fixed.csv` 重渲染。
CSV 必须从0开始并覆盖当前输入；局部修复时对应**带上下文的片段**，不是整首时间轴。
CSV 给的是最终目标音高，会覆盖 `--pitch`，不得借此把移调人声拼回原调伴奏。底层长 CSV 的 int16
长度溢出已修复。自动八度纠错增加 pyin ≥0.9 置信度、连续 ≥80 ms、纠正后 ≤1 半音的保守门限；
这会减少误改，也可能留下更多待手工处理的八度错。

自检现在逐声道查峰值/断点；局部音高或能量异常会使结果变为 WARN（退出码2），即使没有足够 f0，
仍检查能量塌陷。检查参考缺失、时长明显不符、对拍不可信也会告警。`03_vocal.issues.json` 保存定位。
这些是候选异常，混合人声仍可能误报；PASS 只表示这些指标通过，不等于听感无瑕疵。

参数含义修正：`filter-radius` 对本机 rmvpe 分支不生效；`protect` 越小，清音越偏向检索前特征，
0.5 关闭该保护，不能把它当作修有声音高的直接旋钮。`(L+R)/2` 只是 mid，不是主唱提取。

并发：每个任务持有工作目录锁，读取已有任务分轨/修复时也持有来源目录锁；相同目录忙时直接报错。
显式 `--out` 另外按完整目标路径加锁，防止不同任务覆盖同一 MP3。Demucs、RVC、HP5 共用
`voice-lab/.locks/gpu.lock`，不同任务的 GPU 步骤串行，最多等待15分钟。直接调用修过的
`infer_cli.py`/`cover_separate.py` 也遵守这个 GPU 锁；父进程持锁调用子进程时传递持锁标记避免死锁。
锁由操作系统释放，进程被终止后无需删除锁文件。独立 WebUI/旧脚本/其他 GPU 程序不受此锁管理。
需多实例部署时，应共享同一个锁目录（可设置 `COVER_LOCK_ROOT`）；任务分别使用不同 workdir。

当前仍为 CLI，不是常驻服务。高频点歌时可在此基础上增加本机 HTTP 接口与单 GPU worker 队列，
常驻加载模型；服务仍需独立 job ID、目录、排队、取消与超时，不能仅给现有脚本套一个并发 HTTP 层。

## 源音高 → 策略（2026-10-30 定）

判据不是「原唱是男是女」，是**分离出来的人声中位音高**（pyin，只算可信的 voiced 帧）。模型自己会唱的
音域是实测的固定量：p05 207 / p50 300 / p90 373 / p99 462 Hz，0% 的帧低于 150 Hz。拿这个当尺子，
三档已经做成 `--preset`，不用手记参数：

| 源 p50 | 命令 | 展开成什么 | 落在这一档的歌 |
|--------|------|------------|----------------|
| ≥ 260 Hz | `--preset female` | 默认那套，0 半音 | CIRCE 466 / 人は猫 349 |
| 200–260 Hz | `--preset male-thin` | 0 半音 + `index 0.8 / protect 0.4 / presence 11 / lowcut 120 / low-shelf −3` | Lemon 244 / 七百年后 229 |
| < 200 Hz | `--preset low` | +4 半音 + 伴奏同步 +4，EQ 比薄嗓组轻一档 | 真男中音/男低音才会掉进来 |

```powershell
.\env\python.exe scripts\cover.py 歌.wav --slug 歌名 --preset auto     # 跑整首，分离完自己选档
.\env\python.exe scripts\cover.py 歌.wav --slug 歌名 --preset male-thin
```

规矩：

- **预设只改默认值**，命令行显式给过的参数一律优先。`--preset male-thin --pitch 6` 出来就是
  pitch 6 + 薄嗓组的其余参数，`--inst-transpose` 自动跟成 6（人声升了伴奏不升，直接打架）。
- `auto` 要**跑整首**。前奏没有人声，分离残留会让 pyin 报出 136 Hz 这种假低音——20 秒的片段判成
  `low` 是正常的，别拿短片段试 auto。整首《七百年后》实测 229 Hz，稳定落在 male-thin。

**升调不是「变细」的正解。** 想细又不换调，只有薄嗓组这一条。曾经想过的
「人声升 +6 再降 −6、第二遍开 formant preserved」已否决：`rubberband` 保得住共振峰位置，保不住
630–1000 Hz 那道能量缺口，事后变调出来是另一种怪（《人は猫》那轮的原话是「音色不对」）。

## 复现性：能复现质量，不能复现波形

同一首歌重跑两次，人声波形逐样本相关只有 0.3~0.8（demucs 和半精度 GPU 都不是确定性的：
`htdemucs_ft` 两次分离结果相关 0.995，RVC 再一放大就散）。但**音高中位差 0.00 半音、对拍
0 ms、频谱重心和 5.5 kHz 以上能量占比差 <0.1%、响度差 0.1 dB** —— 听感是同一版。

所以别拿「波形对不上」当 bug，看自检那几个数。真正要盯的是音高、对拍、断点、峰值。

## 自检怎么读

跑完自动打印两张表（外加一张破音定位）：

- **成品（混音）**：时长、峰值（>0.995 判 CLIP）、采样跳变（超过 p99.9 的 8 倍判 CLICK）。
- **人声轨对最终目标 F0**：逐帧绝对偏差（中位差 |<0.5| 半音、绝对偏差>1半音的比例 <15%）。
  目标包含所有已执行的移调和局部纠错，不另扣 `--pitch`。有声覆盖不足只表示未验证。
- **源人声诊断**：仅显示音区分歧，不决定音高通过/失败。源轨仍用于能量塌陷和对拍检查。
- **破音定位**：整首切 0.5 s 窗口，列出最可能「破了」的几秒，按严重度排前 5：
  - `音高跳` 窗口里 >25% 的可比有声帧偏离最终目标超过 1 个半音，供定位输出跟随异常。
  - `能量塌` 输出比源同窗口低 12 dB 以上，而源本身有声——RVC 吞字、拼接断点。
  - 相邻窗口合并成一处，所以报的是「哪一秒附近」，不是精确到帧。

音高/对拍/破音定位**只对人声轨做**，混音里鼓和贝斯会把 pyin 带沟里去。
流水线退出码 0 通过、2 有 WARN；单独 `--check` 为 0/1。WARN 不等于处理失败或成品不能试听。
结果写入音频旁的 `.issues.json`，分别包含 pitch_compliance、source_pitch_diagnostic 和
melody_correctness=not_verified，避免把输出跟随与目标旋律正确性混为一谈。
默认比对整首；只想快跑一遍加 `--check-secs 60`。

**整体统计盖得住局部破音。** 「偏离>1半音 2.7%」看着漂亮，可那 2.7% 全挤在两句高音上，
听感就是一串破音——所以破音先看定位表，别拿平均百分比猜。

```powershell

.\env\python.exe scripts\cover.py --check 03_vocal.wav --check-src vocals.wav --check-f0 02_f0.csv
```

## 故障对照（都是真踩过的）

| 症状 | 真因 | 处理 |
|------|------|------|
| 某句「漏字」、人声突然消失 | 多半是错觉：那段 mix 的能量在 `no_vocals` 里，是纯伴奏 | 比对 `no_vocals` 的 side/mid 和峰值，别急着补唱 |
| 音高整体怪、像走了八度 | 组合法/梳状 f0 估计器在人声轨上会报 2 倍频 | 看原始峰值序列：真 f0 的 2/3/4 次泛音都齐，2 倍频只有奇次 |
| 字咬不清（尤其 z/c/s 类塞擦音） | RVC 逐帧按 f0+mel 重建，40~60 ms 的辅音在 mel 里没信息 | 无解，见下「天花板」 |
| 人声发闷、像隔层布 | 650 Hz 附近堆积 + 高频缺失 | 已经在 polish 里处理（debuzz + presence + air） |
| 开头/结尾有爆点 | 拼接点没交叉淡化 | 换段落用 60~80 ms crossfade，拼完查采样跳变 |
| 整首比伴奏短一截 | RVC 输出 40 kHz，重采样长度算错 | 用 `min(len)` 裁齐，别信文件时长 |
| 清音段落有低频嗡鸣 | RVC 给清音帧编了音高 | `breath_splice`：判决用 RVC 轨的音高，替换用源的高通气声 |
| 听感明显破音，自检却报「偏离 2.7% OK」 | 平均统计把局部异常抹平了 | 看「破音定位」那张表的秒数，拿 `--start/--dur` 切出来重跑 |

## 天花板（写在前面，省得再撞一次）

**辅音是硬上限，参数救不回来。** 《人は猫》7–9 秒「絶対」这两个字，音高、时值（偏移 0 ms）、
音量全对，就是咬字不对。已经排除过的路：e100/e125/e150、rmvpe/harvest、index/protect 扫参、
3–10 kHz 频域补高频（实测只涨 1.6/2.6 dB，等于没动）、慢放重唱、换翻唱源。

还没试、按性价比排：①原唱低音量叠一层遮丑（最便宜）②时域辅音移植（整段波形搬，不是搬频谱）
③WORLD 源-滤波器（音色会偏机械）④换带原生辅音的音声合成。详见 `README.md` 末尾那节。

## 模型换代：v2（2026-10-30）

v1 是 363 段 / 单人。v2 在同一个 `spk_embed_dim=109` 的多说话人结构里加了两位客串声线的语料
（鹿乃 38 条、suis 26 条，sid 1 / 2），推理仍然只用 sid 0，所以音色不会漂——实测 LTAS 相关
0.874 → 0.881，等于没动。好处是模型见到的音素组合更多，高音区更稳。

训练到 e120 存的档，`e80 / e100 / e120` 三版拿《人は猫》《Lemon》的同一段对着听，最后定 **e120**。
`feiyu40k_v2.pth` 是最终档，两者等价。

**epoch 只影响音色，不影响音高**：八度修正发生在换嗓之前，三个 epoch 出来的 f0 完全一样。
音准偏离（`偏离>1半音`）三版都在 1.5–3.7% 之间晃，属于噪声级。

## 八度修正（`RVC_F0_OCTAVE_FIX`）

rmvpe 在高音区会整段掉一个八度（523 Hz 判成 261 Hz，持续 200–500 ms）。修法不是按歌写规则，
而是「问第二个估计器」：pyin 再算一遍，逐帧只允许 ±1 个八度的修正，且修正后偏离要落回 3 个半音内
才采纳。所以它对任何歌都成立，不是给某一首定制的。

`cover.py` 调用 RVC 时默认带上 `RVC_F0_OCTAVE_FIX=ref`（`sh()` 里 setdefault，手动设会被尊重）。
代价是每首歌多约 90 s（pyin 那遍）。三档：

| 值 | 做法 | 效果 |
|----|------|------|
| 不设 | 原样 | 《人は猫》8.9% / CIRCE 6.6% 帧偏离 >2 半音 |
| `ref` | pyin 第二意见 | 5.4% / 1.6%（**默认**） |
| `1` | 阶跃检测（掉下去又跳回来） | 更保守，修得少 |
| `acf` | 自相关次谐波判据 | 二次谐波强的人声会过度翻倍，别用 |

已知残余：当两个估计器一起错（CIRCE 50.87 s，rmvpe 和 pyin 都报 261、真值约 523）就没有分歧可
触发，132 ms 仍掉八度。频谱基频仲裁能修这一句，但全曲偏离从 1.6% 涨到 3.0%，不划算，没上。
